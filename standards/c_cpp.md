# C/C++ 代码评审标准

## 正确性

- 检查空指针、越界访问、整数溢出、符号转换和未初始化变量。
- 检查返回码、异常、错误分支和跨模块 ABI/结构体布局兼容性。
- 检查 C/C++ 与 Lua 或其他语言边界的数据生命周期和所有权。

## 内存与资源

- 每个分配路径必须有清晰释放路径，异常和 early return 也要覆盖。
- 检查 RAII 使用是否完整，裸指针、文件句柄、锁、socket 不应泄漏。
- 检查 use-after-free、double free、悬垂引用和临时对象生命周期。

## 并发与性能

- 检查共享状态锁粒度、死锁顺序、原子变量内存序和线程退出路径。
- 热路径避免不必要拷贝、动态分配、虚调用扩散和 O(n^2) 遍历。
- 对缓存、批处理和异步回调检查一致性与失败回滚。

## 可维护性

- 函数边界应表达业务意图，复杂条件需要拆分或命名。
- 头文件应最小暴露，避免无关 include 扩散和宏污染。
- 日志、指标、错误码和注释需要能支持线上排障。

## 测试

- 覆盖正常流程、边界值、错误码、资源释放、并发竞争和回归场景。
- 涉及内存和并发的改动建议运行 ASan/UBSan/TSan 或等价检查。
